# v66：日夜材质响应与屏幕曝光修正

2026-09-10。当前要求是白天、夜晚都更自然，不要整体过暗；不是只修改夜景，也不将本轮称为大厂级、光线追踪或完整动态GI。

## 渲染通路

- 保持Godot 4.7.2 / WebGL2 Compatibility。使用AgX高光响应，白点8.0，日/夜曲线对比1.45/1.30，曝光2.0/2.2。AgX与原ACES的曝光刻度不同，不能直接用数值大小比较最终亮度。
- 实际GPU隔离测试确认：中性空间屏幕拷贝也会再次应用环境曝光。未补偿时，曝光2.0的试验中间灰阶最大偏差约0.14；提高曲线对比后的对照达到0.165。不能仅反复降低灯光或增加滤镜来补偿这个通路问题。
- `meadow_focus.gdshader`保留实际深度驱动的微弱前景柔化，但在线性空间抵消这一次额外曝光。普通sRGB往返在暗灰处仍有约0.027误差，因此匹配当前固定Godot版本GLES的输出传递函数，并数值反解其输入近似。此实现由实际GPU灰阶测试保护，不假设未来引擎的实现永远相同。
- 移除空间屏幕拷贝内的二次黄蓝染色、对比拉伸和暗角。最终饱和度改由原生Environment处理：白天1.0、夜晚0.80，亮度/额外对比均为1.0。这样在景深后绘制的透明水、动物和光晕也参与同一次最终调色。
- 保持最终原生后处理开启；简化SSAO与轻量Glow仍在。没有启用Compatibility不支持的SSR、SDFGI、PCSS等开关来冒充实际效果。

依据：[Godot Environment](https://docs.godotengine.org/en/stable/classes/class_environment.html)、[GLES场景输出源码](https://github.com/godotengine/godot/blob/master/drivers/gles3/shaders/scene.glsl)、[GLES场景/最终处理调度](https://github.com/godotengine/godot/blob/master/drivers/gles3/rasterizer_scene_gles3.cpp)。源码阅读提供了假设，最终以本地4.7.2 WebGL的GPU读回实验验证，不仅依赖上游master。

## 光源与材质

- 日光由偏黄的(1,.90,.70)改为较中性的(1,.95,.84)，能量1.55，保留0.34的定向天空补光。晴天不再把草、石和泥路统一推成亮黄绿。
- 夜晚最终主月光1.02、定向冷色反射补光0.36、均匀环境光0.32；曝光只比日间高10%。首轮主月光0.92/补光0.32的前景略暗，最终增加实际方向光，不加全屏白色遮罩。冷月光与暖路灯、窗灯各有来源，保留遮挡关系。
- 干土粗糙度0.97、草面约0.86、湿岸约0.63；有少量与材质相关的高光。实体草叶保留克制反射，岩石既有细法线/干湿响应继续使用。不把全部物体设置成光滑塑料。
- 路灯照地光、窗格和灯芯颜色减轻高饱和橙色；收紧独立光晕的范围与强度，仍保留52个窗格、路灯柔光晕与月鹿光晕。夜晚远城的绘制补色降低，避免建筑像仍被白天照亮。
- 云的受光方向从实际日/月方向光同步；天体方向也一致。当前月光高度约28°，月面不再为了在画内显示而单独画在错误方向；固定构图中月面可能在画外。云的48个体积近似、漂移时钟及预算不变。

## 验证方法与试版记录

`?render_audit=1`仅在显式诊断网址触发一个96×64独立GPU测试视口，结束后释放，不改场景灯光、资产或用户控制。使用实际景深着色器、8级灰阶、3档曝光，正常补偿要求最大误差不超过2/255；另有故意错误补偿的正对照，确保测试面确实参与渲染。首次测试因测试面被剔除产生无效的零差值，修正朝向/剔除并加入正对照后重新验证，没有将无效样本当作通过。

修正后的首次实际材质测试24个正确补偿样本读回误差均为0；未补偿对照在2.0/2.2曝光下最大误差0.165/0.188。测试不是画风评分，也不证明每个像素或设备都无误差。
