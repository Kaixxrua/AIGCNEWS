# PortShelf · 移植游戏目录

Windows 10 / 11 上的 GitHub 开源移植游戏目录。显示游戏中文名、图片、Stars、中文简介、已核验的支持系统与 Windows 下载地址。支持无人值守发现、下载、上传百度和夸克网盘、创建分享链接并导出中文资料，也保留手动操作。1.6.2 缩短缺失或查找失败海报的本机缓存时间，刷新列表即可读取后端补好的图片；支持按游戏名或项目名联网补图，多游戏引擎也可查找官方海报或项目画面。继续支持网盘授权跨升级保存、对应版本源码分享包。

## 使用

1. 下载与你的电脑匹配的压缩包：普通 Intel / AMD 电脑选 `windows-x64`，Windows ARM 电脑选 `windows-arm64`。
2. 解压后双击 `PortShelf.exe`，默认浏览器会打开本机的游戏目录。无需安装 Go、Python、Git 或额外运行库。
3. 用 Stars 范围、游戏类型筛选目录，也可选填名称进一步缩小范围；点击「查看下载」查看版本、附件架构和大小，直接打开或复制地址。
4. 点击「刷新资料」从 GitHub 更新 Stars 和正式 Release；网络暂时不可用时仍可浏览上次成功取得的资料。
5. 打开「发现更多」，选择最低 / 最高 Stars，或点选快捷门槛，然后点击「按 Stars 查找」。工具自动查找 GitHub 移植游戏项目，无需输入关键词；可继续加载更多结果，或一键添加当前已加载的游戏。也可使用「添加项目」直接粘贴项目地址。
6. 点击侧栏的「退出工具」结束本地进程。关闭浏览器标签不会结束进程；再次双击会打开已经运行的目录。
7. 打开「下载与分享」，勾选游戏与 Windows 架构，选择百度 / 夸克，点击加入队列。两个网盘都不勾选时只下载到本机。
8. 希望持续自动处理时，在同页的「无人值守」面板完成首次授权并开启自动运行，具体设置见下文。

界面中的 Stars 与下载链接带有独立的核对时间。程序附带首次打包时实际查询的公开数据快照；缓存不是实时排名。

更新版本时，请先点击旧版侧栏的「退出工具」，再运行新包中的 `PortShelf.exe`。已有目录与缓存会继续保留；只关闭浏览器标签不会退出旧版进程。

Windows 默认开启「在此电脑记住凭据」，授权连接成功后立即加密保存，**无需开启无人值守**，暂停扫描也不会清除或阻止恢复授权。更新只需替换程序文件，继续使用同一 Windows 用户与同一数据目录即可；默认授权文件在 `%LOCALAPPDATA%\PortShelf\credentials.dpapi`，不随解压目录或软件版本变化。自定义过 `-data-dir` 的用户升级时仍应使用原数据目录。

「连接设置」会显示授权是否已加密保存、正在恢复或保存失败，可刷新状态，也可跳转修改「记住凭据」。短暂断网时保留加密授权并稍后重试，不把临时网络错误当作授权丢失。若旧版此前没有实际保存授权，首次升级后仍需连接一次；服务商令牌或 Cookie 本身失效时也需要重新授权。

## 无人值守运行

- 首次默认最低 **10 Stars**、最高不限、每 **6 小时**扫描、每天最多新增 **10 个游戏任务**，同时上传百度与夸克，架构默认匹配当前程序。可调整 Stars 范围、1–168 小时扫描周期、1–100 个每日上限、网盘与架构。
- 先在设置中连接自己的网盘账号；需要生成中文资料时，再填写独立的 AIGCNEWS MCP Token。点击「开启自动运行」后，程序依次完成发现项目、加入目录、核对 Windows 附件、下载、补全游戏中文名与图片、打包同版本源码、上传两盘与创建分享；两盘都成功后自动清理本地安装包、源码归档和分享包。中文服务有配额；中文失败不阻止文件上传与分享，后续可独立补全资料。源码获取或校验失败则暂停该次上传，保留文件和进度供重试。
- 扫描会分批继续发现，跳过没有所选 Windows 架构附件的项目。后续扫描再次遇到项目且正式 Release 的版本或附件发生变化时，可为新发布建立任务；相同发布及选项不会反复新建。GitHub 搜索范围与候选上限仍适用，并不承诺监控所有 GitHub 游戏。
- 「立即扫描」可提前执行一次已保存的配置。「暂停自动运行」会暂停自动任务，重新开启后继续；已经开始的手动任务不受影响。手动取消的任务不会被自动恢复。
- 临时断网、服务暂不可用等错误会延后重试，任务卡显示下一次重试时间。登录失效、验证码、权限或空间不足等问题会提示需要处理；并非所有失败都会自动重试。重试会核对并复用已经完成的步骤。
- 配置与任务进度保存在本机，开启状态下重启可恢复自动队列。Windows 上勾选「记住凭据」后，GitHub / AIGCNEWS Token、百度 Cookie 与夸克令牌使用 **Windows DPAPI** 加密保存到本机 `credentials.dpapi`，仅当前 Windows 用户可解密；保存和恢复与扫描启停独立，一次性夸克授权码不保存。取消勾选并保存设置会清除这份加密凭据。
- Windows 上开启「登录 Windows 时后台启动」后，会创建当前用户的启动项，登录后在后台运行，不自动弹出浏览器；双击程序仍可打开界面。启动项仅在自动运行开启时生效，升级后应运行新程序并确认设置。电脑必须开机、联网，程序需要持续运行。
- 非 Windows 平台禁用记住凭据与 Windows 登录启动，不会退回明文保存；自动处理仅在当前进程运行期间进行，重启后需重新提供授权。
- 自动将已完成或部分完成的资料写入数据目录下的 `exports` 文件夹，包含 JSON、CSV 与 Markdown；可在面板中打开目录。资料记录真实支持系统、中文简介、版本、来源、文件摘要、分享链接及实际提取码。
- 首次网盘授权、失效后的重新登录与验证码仍需本人完成。程序会显示需要处理的原因，不会绕过服务商验证，也不包含闲管家商品发布、价格设置或交易操作。

## Stars 筛选

- 「我的目录」直接使用最近核对的 Stars 筛选，无需联网；有 Stars 条件时，尚未核对 Stars 的项目不计入结果。
- 「发现更多」与无人值守默认从 10 Stars 起查找，也可选择快捷门槛，或自行填写上下限。留空表示不限，`0` 是有效数值，上下限均包含边界。
- 自动发现按源码移植、重编译、重制等描述与标签查找公开、未归档项目，并排除明显的项目合集、SDK 和模拟器。每批读取 100 个候选，筛选游戏后按 Stars 排序；点击「加载更多」继续追加，跨批重复项目自动合并，不再截断为 24 项。
- [GitHub 搜索 API](https://docs.github.com/en/rest/search/search#about-search) 每次查询最多开放前 1,000 个候选。达到上游限制或返回不完整结果时会提示，可收窄 Stars 范围后继续查找。候选数量不等于实际游戏数量；未匹配描述的项目仍可通过地址添加。
- Stars 反映社区关注数，搜索结果不保证包含 Windows 发布附件。加入目录后可核对实际下载信息。

## 一键添加、游戏中文名与图片

- 一键添加只保存当前已加载的查找结果，跳过已在目录中的游戏；显示成功、跳过和失败进度，可停止后继续补添。批量添加使用本次 GitHub 查询取得的资料，不会逐个重复查询 GitHub。打开游戏详情时再核对 Release 和下载附件。
- 游戏中文名和简介由 AIGCNEWS 的项目富化服务根据公开项目资料生成，已有结果直接读取并缓存。中文名作为卡片主标题，同时保留项目名、原文游戏名和仓库地址；无法确认时显示「中文名待确认」，不把仓库名直接当作中文游戏名。可以展开查看 GitHub 原始简介。
- 确认具体游戏名后，AIGCNEWS 富化 Agent 会按每款游戏的中英文名主动联网搜索，优先查询游戏官网、游戏商店、游戏资料库与封面站，无匹配时再扩大范围；不限于初始目录中的游戏。它读取搜索结果页面，只能选择页面中实际找到的图片，并核对游戏、版本及图片用途；不能凭模型记忆编造图片地址。README 图片作为补充来源，不能替代联网查找。
- OpenRA 等对应多个游戏、无法确认唯一原作的项目，会以已核验的项目名称查找自身的官方海报或游戏画面；不会随意选择其中某款游戏的封面，也不会虚构一个原作名称。独立游戏或自由素材替代项目即使记录了关联原作，也可按项目名称寻找自己的画面，不把关联商业游戏的封面当作该项目的海报。这些项目同样支持手动、批量和自动补图。
- 找到的图片必须实际下载，通过图片解码和大小检查后，再由现有模型查看缩略图像素，结合仓库与中文简介核对内容。占位图、纯标志横幅、错游戏或错版本的图片会被拒绝；不能核实的结果不会当作成功海报。通过核验后转换为 JPEG 缓存到 AIGCNEWS，以固定图片地址供卡片加载，并保留原网页来源链接；海报与游戏画面分别标明。不生成虚构海报，也不保证所有项目都能找到合适图片。
- 生成缺失的中文简介需要在设置中填写你自己的 AIGCNEWS MCP Token，可从 [AIGCNEWS MCP 页面](https://aigcnews.cn/mcp) 创建。它与 GitHub Token 分开；是否跨重启保存由无人值守的「记住凭据」设置决定。
- 可逐项生成，也可批量补全当前结果的中文名与图片。升级前只有简介的项目也会显示补全入口，补全过程保留已有简介。生成在服务端排队，使用账户的程序化 API 配额；缓存查询、同一进行中的任务不会重复扣额度。限流、失败或服务尚未就绪会明确提示，不影响游戏查找和添加。
- 已有中文资料的游戏或项目可点击「联网重找海报」，包括已有截图或图片加载失败的项目；只补图时不会重新生成中文名与简介，但联网 Agent 会调用现有富化模型，实际新任务使用现有富化额度。搜索中保留原有文字与图片；失败不会把旧图片冒充新结果。批量补全处理缺失资料及已发现加载失败的图片，正常图片会跳过。开启富化的自动下载任务遇到已有中文资料但缺图时，也会在冷却结束后请求补图；图片未找到不阻塞文件传输。
- 单项与批量任务会自动核对生成进度，最长等待 5 分钟，期间保留已有文字与图片；批量任务在当前项目完成后才提交下一个。超过等待窗口会暂停核对和后续批量提交，可点击「核对生成进度」继续读取结果。刷新页面或重启后也会读取此前尚未完成的任务；这些操作只查询进度，不重新提交付费生成。下载任务的资料步骤同样最多等待 5 分钟，仍未完成时提示待补充并继续文件传输。
- 新联网搜索没找到匹配图片时，1 小时后可重试；来源暂不可用时，5 分钟后可重试；成功后手动再次搜索至少间隔 60 秒。旧版尚未进行联网搜索的项目不受旧版查图冷却阻止。图片加载失败只显示重试入口，不会自动发起付费搜索或循环刷新。
- 中文结果在本机与服务端缓存；正常有图的资料本机有效期为 7 天。缺图或最近查图失败的资料（包括仍保留旧图的项目）采用 60 秒短缓存，重新打开或刷新游戏列表时，距上次读取满 60 秒便自动读取服务端已补好的结果；这只是查询缓存，不发起付费生成，也不持续循环请求。网络暂不可用时保留已有中文和图片。
- 已核验结果正常缓存，没有按仓库预设的海报映射。用户点击「联网重找海报」仍会走相同的联网搜索、实际下载和图片内容核验流程。

## 收录内容

初始目录包含 Ship of Harkinian、Zelda64 Recompiled、OpenRCT2、OpenRA、DevilutionX、CorsixTH、UZDoom、dhewm3 和 OpenMW。项目简介和原作名称由目录整理；Stars、版本及附件来自 GitHub API。

下载链接指向各项目自己的 GitHub Release。部分移植需要自备原版数据或 ROM，详情中的「运行要求」链接到上游说明。没有 Windows 附件时会显示相应状态，并保留项目发布页入口。

目录、任务与导出资料中的支持系统，只按实际 Release 附件证据标注，例如 Windows x64、Windows ARM64、macOS、Linux x64；尚未核验或证据不足时显示「支持系统待核实」。发现结果不会根据项目名称或简介猜测系统，中文富化也不替代附件核验；能否正常运行仍请以上游说明为准。

## 批量下载、网盘上传与分享

- 下载与分享可以沿用目录的 Stars、名称和类型筛选，全选当前结果后自动分批入队；按所选架构选择正式 Release 中的 Windows 附件，优先便携压缩包，排除调试符号和其他系统的附件。只下载到本机时保留原始发布附件；选择网盘时另外获取对应源码并打包分享。
- 文件默认保存在缓存目录下的 `downloads` 文件夹，可直接在任务页面打开文件夹。每款游戏独立目录，上传到各网盘的 `PortShelf` 文件夹时名称包含仓库与版本。
- 每个网盘任务依次下载、准备中文资料、获取源码、生成分享 ZIP、上传所选网盘、生成分享链接。源码按该 Release 的标签解析到固定提交，获取该提交的完整 GitHub 源码归档，校验 ZIP 结构及内容后打包；不会使用默认分支代替，也不会在源码失败后只上传游戏附件。单个发布附件上限 8 GiB，源码压缩包上限 2 GiB，源码解压后内容校验上限 8 GiB；以流式方式处理，不执行下载内容，不向下载服务器发送网盘凭据。
- 分享 ZIP 包含原始发布附件、对应源码 ZIP、源码根目录的许可证副本、中文说明与清单。清单记录仓库、发布版本、固定提交、来源和摘要。原始附件及源码 ZIP 的字节保持不变；完整源码归档中的许可证仍保留。Git 子模块、Git LFS 外部对象与原版游戏数据不由 GitHub 源码归档自动补齐，说明文件明确标注；这里的源码包不是可保证离线构建的全部依赖包。
- 校对发布文件大小；上游提供 SHA-256 时核对其摘要，同时保存本地 SHA-256。重试会重新验证仍在本机的文件，复用同版本下载和当前登录会话中已成功的网盘步骤。未完成的本地下载会从头重下；分享失败时保留成功上传的网盘文件以重试分享。
- **自动清理本地文件**：同一任务选择百度和夸克，且两边均上传成功、已返回有效且未过期的分享链接后，程序再次核对本地文件大小与 SHA-256，仅删除该任务记录中的发布附件、源码归档和分享 ZIP；任务记录、中文资料、系统信息、导出资料及两盘链接均保留。手动与自动任务都适用，启动新版也会继续处理已完成任务的清理。
- 只下载到本机、只选一个网盘、任一上传或分享失败、暂停或取消的任务都保留本地文件。文件被修改、路径不安全或仍有其他未完成任务使用时也保留，并显示原因；文件占用等清理失败会在程序运行时继续重试。不会删除游戏目录中的其他文件或解压后的内容。
- 清理完成后显示「本地文件已自动清理」，导出包含清理时间，不再把旧路径当作可用文件。仅补中文简介或续建分享可复用网盘文件，无需重新下载；更换网盘账号等需要重新上传的情况会重新下载。百度与夸克的结果分别记录，一家失败不会抹掉另一家的成功结果；停止任务不撤销分享。
- 任务保存在 `transfers.json`。重启后，未完成的手动任务暂停并可手动继续；自动任务按无人值守开关恢复。Windows 加密授权恢复并通过账户核验后，可以复用相应网盘步骤；更换账号或建立新授权会重新核对会话，不把旧账号的链接当作当前账号的结果。已有历史资料仍可导出。不要把“清理已完成记录”当作删除文件，它只清理本机任务历史。
- 升级前已完成的单文件分享保留为历史记录，不会自动批量重传，也不显示「含源码」。新建或继续执行的网盘任务使用新版分享包；历史单文件链接不会冒充新版 ZIP 的上传结果。修改中文资料不会自动重传已经生成的分享包，后续补全内容可通过资料导出获取。
- 可复制单项中文资料，或导出 JSON、CSV、Markdown，包含名称、版本、架构、支持系统、Stars、中文简介、运行要求、上游来源、文件摘要及两盘链接和实际提取码。导出不含登录凭据；中文生成失败会提示待补充，文件传输继续。
- 分享期限可选永久、1 天、7 天、30 天。百度使用提取码分享，提取码可指定 4 位字母或数字；留空自动生成。夸克可选公开或私密分享，私密提取码由官方服务生成，以任务结果为准。
- 不包含闲管家商品发布、价格设置或交易操作。原始发布包保持不变；分享和分发前应查看项目许可证，开源引擎并不自动包含原版游戏素材。

### 连接百度网盘

1. 在设置中打开百度网盘官网并登录自己的账号。
2. 按设置中的帮助，从自己浏览器的百度网盘请求中复制 Cookie，粘贴到本机 PortShelf 设置框，点击连接。需要包含 `BDUSS` 与 `STOKEN`，不要复制整条请求或发给其他人。
3. PortShelf 用同一网页登录会话上传和分享。该分享方式使用百度网页接口，可能因网页登录失效、验证码、平台限制或接口变化而需要重新登录；这不是一个已获百度审核的独立 OAuth 应用。

### 连接夸克网盘

1. 在设置中点击获取夸克授权页面，再打开返回的官方网盘授权链接。
2. 在夸克页面登录并完成授权，将页面给出的授权码复制回 PortShelf，点击连接。
3. 工具按照官方 Quark Drive Agent 协议换取并刷新令牌。Windows 勾选记住凭据时，无论是否开启无人值守，都会加密保存授权后的令牌和后续续期结果；一次性授权码不保存。它不安装或运行外部 CLI，也不需要 Node.js。

未启用加密保存时，网盘凭据仅保留在当前进程内存。登录凭据始终不写入浏览器存储、本地任务记录、资料导出或分发包；启用记住凭据时仅在独立的 DPAPI 文件中保存可恢复的凭据。只有相应官方服务会收到自己的凭据。下载队列运行时请先停止相关任务，再更换网盘账号。

## 网络与缓存

- 更新资料需要访问 `api.github.com`；任务下载需要访问 `github.com`、GitHub 的官方发布附件域名和源码归档域名 `codeload.github.com`。新版联网海报由浏览器从 `https://aigcnews.cn/api/media/site/game-posters/` 加载；旧缓存仍支持限定 GitHub 图片域名与 `upload.wikimedia.org`。联网搜索、网页读取和图片验证在 AIGCNEWS 后端执行，使用已有搜索组件、模型与出站网络，客户端无需新增搜索服务账号。
- 读取或生成中文资料需要访问 `https://aigcnews.cn/api/v1/projects/descriptions`。新版使用 `gameDetails=true`，请求只提交公开仓库名和资料类型；AIGCNEWS 在服务端查询公开资料并调用已有富化模型，模型凭据不会进入下载包。服务端尚未升级时会提示新版资料暂不支持，保留已有简介。
- GitHub、AIGCNEWS 和百度连接支持 `HTTPS_PROXY` / `HTTP_PROXY` 环境变量；如需代理，请在启动前设置。浏览器的系统代理设置不会自动传给本地工具。夸克接口和分片存储使用经过公网地址校验的直连。
- 网盘请求只访问百度固定网盘 / PCS 接口、夸克官方 Agent 接口及其指定的阿里云 OSS 分片地址。授权失败时会显示错误，不尝试绕过验证码或账号限制。
- GitHub 匿名 API 有请求限额。遇到限流，可稍后重试，或在设置中填写自己的 GitHub Token。只查询公开仓库，无需授予私有仓库写入权限。
- Token 的跨重启保存由无人值守的「记住凭据」设置控制，Windows 使用 DPAPI 加密；其他平台或未启用保存时仅保留在进程内存。不写入普通资料缓存或分发文件。
- 缓存默认位于 `%LOCALAPPDATA%\PortShelf\library.json`。可以用 `PortShelf.exe -data-dir D:\PortShelfData` 指定位置。
- 程序仅监听 `127.0.0.1` 的随机端口；本机界面使用每次启动生成的会话凭据。

## 源码构建

需要 Go 1.25 或更新版本；本模块没有外部 Go 依赖。

```sh
cd tools/portshelf
go test -race ./...
go vet ./...
go run . -no-browser
```

中文显示、队列与无人值守界面逻辑可另用 `node --test tests/*.test.cjs` 验证；已有 Playwright Chromium 环境时可运行 `tests/identity.browser.cjs`、`tests/posters.browser.cjs`、`tests/poster-search.browser.cjs`、`tests/poster-batch.browser.cjs`、`tests/pending-recovery.browser.cjs`、`tests/transfers.browser.cjs` 与 `tests/automation.browser.cjs`，通过 `PORTSHELF_PLAYWRIGHT_MODULE` 指定模块路径。Node 只用于开发测试，Windows 用户运行工具不需要安装。

在 Linux / macOS 上交叉构建两个 Windows 版本：

```sh
python3 build.py --out /absolute/path/to/portshelf-dist
```

或在 Windows PowerShell 中直接构建本机版本：

```powershell
go test ./...
go build -trimpath -ldflags="-s -w -H=windowsgui" -o PortShelf.exe .
```

打包脚本先运行测试和静态检查，再输出 EXE、ZIP 和 SHA256SUMS。压缩包的 `source/` 目录包含对应版本的完整源码，可以进入该目录直接重新构建。Linux 上的测试与交叉构建不能替代 Windows 实机验收：双击启动、DPAPI 加密与重启解密、登录后台启动、目录打开，以及真实账户的网盘授权、上传与分享仍需在 Windows 上核验。
