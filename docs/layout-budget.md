# 版面预算（桌面与手机）

`frontend/scripts/layout-budget.mjs` 把改版后的人工复测固定成一条命令。它分桌面、手机两套跑，逐个组合检查，超预算的列出原因。

- **桌面**：11 项 × 4 档视口（1024×640、1350×657、1536×730、1920×960）× 中英文，共 88 个组合。
- **手机**：21 项 × 3 档视口（360×740、390×664、430×740）× 中英文，共 126 个组合。按触屏手机模拟：`isMobile`、`hasTouch`、3 倍像素密度，用 Android 手机的 UA。UA 里留着 `HeadlessChrome`，站点按自动化流量计，不算访客。

每个组合都查以下三项：

- **落地页**：页面就绪后，地址的路径要等于这一项的地址（个别项另行指定，可以给几个）。要登录的页面会把游客送回首页，没有这条就会量错页面。桌面原来的「订阅」一项就是这样，量到的其实是首页加登录弹窗；现在拆成两项：自己点开的登录弹窗（login），和游客被拦下时看到的首页加登录框（gate）。被转走的页面，首页的代码没下完时地址还停在原处，所以最多等 15 秒，地址换过去再开始量。
- **布局偏移**：页面就绪、落定后再等 3 秒，累计非用户输入引起的 layout-shift，上限 0.1（Core Web Vitals 的「良好」线）。有弹窗的项算到弹窗打开并稳定为止；点开弹窗那一下算用户输入，它引起的位移不计。
- **横向溢出**：分两种情况。
  - 文档比视口宽，或者手机浏览器为了装下过宽的内容把视口撑宽（`innerWidth` 大于设定宽度）。此时列出最外层的越界元素。固定定位的背景层、底栏、弹窗只是跟着视口变宽，不算起因。
  - 内容出了屏幕边。站点外壳 `.app-shell` 和 body 都裁掉横向溢出，所以多数溢出不会让页面横滑，而是让内容被屏幕边裁掉。有字或能点的元素越出视口，且只被整页级的容器裁住，就算失败。整页级指横跨视口的裁切层，或高过半屏的滚动层。窄于视口的横滑条、走马灯由组件自己裁切，不算；整个停在屏外的元素（抽屉、跳转链接）也不算。

另有几项只对部分页面检查：

- **首屏条目**：
  - 桌面数完整条目：条目上下沿都在视口里，两处命中测试都打在条目上，没被报头、页脚、浮层或滚动容器挡住。
  - 手机一屏装不下几张整卡，改数露头条目：顶边往下 24px 都在视口里，顶边下 2px、22px 两处命中测试都打在条目上，没被报头、底栏或浮层挡住。
  - 下限按宽度分中文、英文两个，下限为 0 的组合不比数量。页面上的条目总数不到下限时（比如清晨推文墙按账号折叠后只剩几张卡），改为要求全部条目都落在首屏。页面上一条都没有算失败，多半是数据没取到。
- **整块落在首屏**（仅桌面）：会员对比表（≥1350 宽），以及 MCP、dsh 两页的主按钮「复制给 Agent 的配置提示词」。
- **列表键盘流**（仅桌面）：适用于简报、项目库和推文墙。
  - 按 `j`，光标亮到视野里的条目并取得焦点；再按 `j` 换到下一条，按 `k` 回到上一条。
  - 按 `?` 打开快捷键表，按 `Esc` 关闭；再按一次 `Esc` 收起光标。
- **弹窗**：先按 `taps` 依次点开（手机用触摸，桌面用鼠标），等弹窗出现后再等 1 秒。
  - 弹窗外层要整个落在屏内。
  - 弹窗出现后不能自己挪位置。从外层第一次画出来起逐帧记它的上下沿，累计挪动超过 4px 算失败。只看 layout-shift 不够：登录框因第三方登录按钮晚到整张跳 56px 时，Chrome 有的轮次一条偏移都没报。网页字体刚加载完、弹窗里又没增删内容的那一帧不计，那是字体闪动，算在布局偏移里。
  - 里面每个看得见的控件逐个滚到中间，其可见部分正中的命中测试要打在它自己或它的 label 上。控件指链接、按钮、输入框和可聚焦元素；小于 4px 的或隐藏的跳过。

固定条件为浅色主题、紧凑档（站点默认）、减少动态、游客身份。脚本只读：`/api` 下的非 GET 请求一律在浏览器里拦下，回一个空的成功响应（204），不发到站点；也不连实时事件流，所以可以直接对着生产跑。写请求不能直接掐断：游客只有访问计数这一个写请求，掐断后站点会当成连不上主站，再碰上一次网络抖动，就弹出「换备用入口」的提示，压在弹窗上。没加载完的组合会自动重跑一次。退出码 0 表示全部在预算内；1 表示有组合超预算，原因逐条列出。

## 测哪些页面

桌面：简报（钉在 10-03 那一期）、项目库、推文墙、UI 灵感库、会员、MCP、网页收藏（`/projects?source=website`）、dsh、未知地址的「页面不存在」页（not-found，`/no-such-page`），从 dock 账号按钮打开的登录弹窗（login），以及游客打开订阅页时看到的首页加登录框（gate）。

不测的页面：订阅（`/subscriptions`）和会员结账（`/membership/checkout`）要登录，游客打开只会被送回首页、弹出登录框，这个场景用订阅页测一次，就是 gate 项；监控（`/monitor`）只对管理员开放；`/login` 不是路由，登录走弹窗，即上面的 login 项；第三方登录的两个回调页只是中转，一打开就要兑换一次性登录凭据（写请求），脚本只读，测不了。

## 运行

测候选版本（本地构建，`/api` 转发到生产）：

```bash
cd frontend
npx vite build
VITE_API_PROXY_TARGET=https://aigcnews.cn npx vite preview --port 4173   # 另开终端
npm run check:layout
```

测生产的某个边缘：

```bash
LAYOUT_BASE_URL=https://aigcnews.cn LAYOUT_RESOLVE=aigcnews.cn=<边缘 IP> npm run check:layout
```

| 变量 | 作用 |
|---|---|
| `LAYOUT_BASE_URL` | 被测站点，默认 `http://127.0.0.1:4173` |
| `LAYOUT_RESOLVE` | 把域名钉到某个边缘，如 `aigcnews.cn=<边缘 IP>`；钉了就不走代理 |
| `LAYOUT_PROFILE` | 只测一套：`desktop` 或 `mobile`，缺省两套都测 |
| `LAYOUT_PAGES` | 只测这几项，逗号分隔，如 `report,projects`；同名的项两套里都会测 |
| `LAYOUT_CONCURRENCY` | 同时开几页，默认 3；两套共 214 个组合，并发 4 时本地构建约 3 分半（200 个组合时实测） |
| `LAYOUT_REPORT_DIR` | 超预算的组合截一张图存到这里 |
| `CHROME_PATH` | 换用指定的 Chromium，缺省用 Playwright 自带的（`npx playwright install chromium`） |

缺 Chromium 系统库的机器，用 `LD_LIBRARY_PATH` 指向补齐的库目录。

## 预算从哪来、怎么改

桌面下限取自 2026-10-03 的生产实测。简报钉在 10-03 那一期，UI 灵感库的网格固定，这两页直接用实测值；项目库和推文墙的数据每天在变，留了 1～3 条余量。实测基线如下（中文/英文，单位：条）：

| 页面 | 1024×640 | 1350×657 | 1536×730 | 1920×960 |
|---|---|---|---|---|
| 简报（10-03） | 0/0 | 2/0 | 2/2 | 7/5 |
| 项目库 | 3/3 | 5/3 | 7/5 | 10/10 |
| 推文墙 | 3/3 | 4/4 | 5/5 | 8/8 |
| UI 灵感库 | 3/3 | 10/10 | 12/12 | 21/21 |

英文导读比中文长，所以简报在 1024 宽（中英文）和 1350 宽（英文）时，首屏没有一条完整条目，下限记为 0。这几个组合只检查偏移、溢出和键盘流。

手机下限取自 2026-10-04 的实测（本地构建，数据取自生产），单位是露头条目：

| 页面 | 360×740 | 390×664 | 430×740 |
|---|---|---|---|
| 首页 | 1/1 | 0/0 | 1/1 |
| 项目库 | 1/1 | 1/1 | 2/1 |
| UI 灵感库 | 1/1 | 0/0 | 1/1 |
| 简报（10-03） | 1/1 | 1/1 | 1/1 |
| 推文墙 | 2/2 | 2/1 | 2/2 |

首页、UI 灵感库和简报直接用实测值。项目库和推文墙的卡片高度随数据变，下限统一记 1。390×664 偏矮，首页和 UI 灵感库的第一条露不出头，下限记 0。

如果改版有意减少首屏条目，在同一个提交里改 `PROFILES` 里的下限，并在提交说明里写明前后数字。

偏移超线的，多半是网页字体或数据晚到，页面重新折行。先用 `LAYOUT_PROFILE`、`LAYOUT_PAGES` 只测那一项，确认能复现；再看 `layout-shift` 条目的 `sources`，找出被推动的节点。偏移量随网络时序浮动，靠近上限的组合要多跑几次。弹窗跳位不一定有 layout-shift 记录，以「弹窗出现后又挪了位置」这条为准。

手机正文用 Inter（`mobile-reading.css`），目前没有预加载，要等首帧排版用到时才请求，晚到换上时可能让文字重新折行。像桌面那样在 `index.html` 里预加载可以避免，但在 Slow 4G 模拟下首次内容绘制会晚约 0.66 秒，所以暂未采用。宽度会随字体变化的地方要自己稳住，比如 UI 灵感库的排行签在手机上固定排成三列两行。把字体人为推迟 4 秒，各页偏移仍在 0.1 以内，最高的是 dsh 390 宽英文，约 0.08。

## 现状：还没进 CI

受信 CI 由 `scripts/ci/local_ci.py` 按 `baseline_sha` 执行 `.github/workflows/contract-baseline.yml`。它只认五个固定 job，跑步器模板里也没有浏览器。要接进 CI，需要做三件事：
1. 在 frontend-build job 里加步骤：装 Chromium，起 `vite preview`，`/api` 改用录好的固定数据，再跑预算；
2. 在跑步器模板里装 Chromium 依赖库；
3. 显式提升 `baseline_sha`。

这属于受信边界变更，需要单独批准。批准之前的做法：改动版面（桌面或手机）的提交，提交前先在本地跑一遍；发布后再对两个边缘各跑一遍。
