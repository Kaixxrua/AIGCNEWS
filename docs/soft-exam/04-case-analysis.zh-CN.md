# 04｜下午案例分析学习手册

> 用时：第 26～33 周，每周约 6～8 小时。
>
> 目标：在有限时间内识别约束、画出结构、做出取舍，并用“方案—风险—验证”覆盖分点得分。
>
> 边界：不要求写代码。代码题干中的实现细节，只转化为组件职责、数据流和故障原因。

## 1. 下午案例到底考什么

案例题通常给出项目背景、架构现状、故障或改造目标，再用多个小问考察概念和设计判断。不要把答案写成技术名词清单。每个小问都要回到题干：

```text
题干事实 → 约束/质量属性 → 问题定位 → 方案 → 替代方案与代价
         → 故障/安全/运维 → 验证与恢复
```

参考答案不是唯一答案。合理的替代方案可以得分，但必须覆盖题目约束并解释为什么这样选。

## 2. 90 分钟答题节奏

| 时间 | 动作 | 检查点 |
|---:|---|---|
| 0～8 分钟 | 通读题干，圈出目标、数字、限制词和故障 | 不急着写方案 |
| 8～15 分钟 | 标注每问的知识域和得分动作 | 定义/原因/方案/比较 |
| 15～25 分钟 | 画现状图和目标图 | 标组件、边界、箭头 |
| 25～70 分钟 | 按小问作答 | 一问一段，先结论后理由 |
| 70～82 分钟 | 补权衡、风险、监控和恢复 | 避免只写 happy path |
| 82～90 分钟 | 对照题干逐项查漏 | 每一问都有明确回应 |

如果题目要求计算，先写公式、单位和假设，再给结果。没有题设数字时不要自行伪造生产数据。

## 3. 通用作答模板

### 3.1 约束提取

先列出：

- 功能目标：读、写、搜索、推送、流式或批处理；
- 规模约束：请求量、数据量、峰值和增长（无数字则声明假设）；
- 质量属性：性能、可用性、可靠性、一致性、安全、可维护性；
- 运行约束：外部依赖、部署、成本、团队和发布窗口；
- 明确不在范围内的内容。

### 3.2 方案表达

```text
我选择 X，原因是它优先满足题目中的 Y 约束。
它的代价是 Z，因此用 A 监控/限流/补偿控制风险。
如果约束改成 W，则考虑替代方案 B。
```

### 3.3 故障闭环

至少写出：超时/失败如何被发现；用户如何降级；任务如何重试；如何避免重复副作用；如何告警；依赖恢复后如何补偿和验证。

## 5. 题型一：事实主库与派生索引

### 题干

一个内容聚合平台将结构化事实写入关系数据库，同时更新向量检索和图关系索引。要求主写可靠，搜索允许短暂延迟；某个派生索引不可用时不能阻断其他来源入库。

### 自测要求（第 28 周）

20 分钟写出：

1. 为什么不建议把三个存储放进一个跨库事务；
2. 如何保证最终收敛；
3. 派生索引失败时用户看到什么；
4. 如何防止重试重复写入。

### 参考答案要点

- 关系数据库是事实主库，向量/图索引可重建，跨库事务会增加协调、锁和故障复杂度；
- 主库成功后记录待处理任务或事件，异步更新派生索引，失败重试、告警和定期补建；
- 搜索暂时缺少新内容，但基础列表和事实读取仍可用；
- 以内容唯一标识、版本或幂等键去重，消费者重复执行不改变最终结果；
- 监控索引滞后、失败数和补偿成功率。

### 评分 rubric（20 分）

主库/派生定位 4 分；最终一致路径 5 分；降级 4 分；幂等 4 分；告警/恢复 3 分。只写“使用分布式事务”而没有说明必要性和代价，不能获得完整分。

## 6. 题型二：缓存或 Redis 故障

### 题干

系统使用 Redis 做页面缓存、限流和一次性验证码辅助存储。Redis 短时不可用，访问量仍然很高。

### 自测要求（第 29 周）

15 分钟分别写出三种用途的处理方式，不要笼统写“全部降级”。

### 参考答案要点

- 页面缓存：有限度回源 PostgreSQL，设置超时和并发保护，非核心内容可返回旧值或简化结果；
- 限流：根据安全等级采用本地保守限流、拒绝高风险操作或短时 fail-open，不能一概而论；
- OTP：验证码和尝试次数属于安全控制，缓存失效时宁可暂时拒绝验证/发送，也不能无限放行；
- Redis 恢复后重新建立缓存和观测命中率，避免瞬时回源风暴。

### 易失分点

“Redis 只是缓存”“Redis 挂了就重启”“所有请求直接打数据库”都没有区分业务重要性、风险和恢复过程。

## 7. 题型三：调度单活与横向扩容

### 题干

平台在单进程中使用调度器执行采集、补采和派发任务。为了提高 API 容量，准备启动多个应用实例。

### 自测要求（第 30～31 周）

25 分钟画现状/扩容图，并回答：重复任务如何产生？有哪些治理方案？各自代价是什么？

### 参考答案要点

多个实例都会注册并触发同一进程内任务，可能重复采集、重复派发或竞争资源。可选方案：

1. 保持调度器单活，API 实例只处理请求；简单、边界清楚，但调度器成为独立运行单元；
2. 使用分布式锁/租约选主，故障可切换，但要处理租约过期、脑裂和时钟/网络问题；
3. 把任务交给外部任务平台或队列，扩展性和可观测性好，但增加基础设施和运维成本。

无论方案如何，任务本身还要幂等、可重试、可观测。

### AIGCNEWS 当前事实

当前文档明确 APScheduler 为进程内调度，并有单实例假设；这不是“已经完成多实例治理”的事实。论文和答题中应把治理方案写成设计判断。

## 8. 题型四：SSE、MCP 与公网安全边界

### 题干

系统需要对外提供 HTTP API、SSE 流式响应和独立 MCP 协议服务。匿名用户可访问公开能力，登录凭证可获得受限能力；代理不能缓冲 SSE。

### 自测要求（第 30 周）

20 分钟画边界图，说明：

- TLS、反向代理、API、MCP 各自的职责；
- 认证和授权的区别；
- 无效 Token 为什么不能悄悄降级为匿名；
- SSE 长连接需要哪些代理和超时考虑。

### 参考答案要点

nginx 位于公网边界，可承担 TLS、路由、限流、安全头和 SSE 反代配置；API 和独立 MCP 服务分别处理自己的协议契约。认证识别身份，授权判断权限和 scope。显式提供但无效的 Token 应返回 401，不能降级为游客，避免错误凭证意外获得公开或错误行为。SSE 需关闭代理缓冲、配置合理读超时和心跳，并处理客户端断开及服务端资源释放。

### AIGCNEWS 当前事实

`/api/mcp` 由独立 Go 服务承载；网站配置页受登录保护；nginx 是公网边界。不要把网站配置页的登录保护误写成 MCP 公开运行平面也必须登录。

## 9. AIGCNEWS 综合案例

### 题干

AIGCNEWS 从多个来源采集内容，经过标准化和富化写入 PostgreSQL，并建立 Redis、Milvus、Neo4j 等派生能力。系统还提供 Dashboard、项目库、RSS、订阅、MCP 和 RAG。请分析：

1. 如何隔离单源失败；
2. 为什么主库和派生索引采用最终一致；
3. Milvus 或 Neo4j 不可用时如何降级；
4. 为什么 MCP 独立服务不意味着所有服务都应微服务化；
5. 横向扩展时 APScheduler 有什么风险；
6. 如何保护外部 webhook 或媒体 URL；
7. 如何观测采集滞后、索引滞后和派发重复。

### 参考作答结构

先画“数据源—采集—主库—派生—消费”的图，再按 1～7 编号回答。每个回答必须有“当前事实/设计建议”标识。可写：单源隔离和任务记录避免一个上游拖垮全局；主库先落事实、派生异步收敛，牺牲短暂搜索新鲜度换取边界简单；检索失败回退结构化查询或提示结果不完整；MCP 有独立协议与扩展边界，其他模块按领域和运维收益决定是否拆分；调度需要单活/选主/外部任务平台；外部 URL 做目标解析、私网/回环/重定向策略限制；监测成功率、处理延迟、索引滞后、队列积压、重复投递和恢复耗时。

## 10. 阶段验收与补救

第 33 周完成三套完整案例，至少两套在 90 分钟内完成且 ≥60/100。每份答卷必须满足：

- 每小问都有明确结论；
- 至少一张图包含边界和箭头；
- 关键方案有替代方案与代价；
- 至少出现一次幂等/重复处理；
- 至少出现一次监控、恢复或验证；
- 能区分事实、题设假设和设计建议。

如果低于 60 分：把失分按“读题、概念、结构、权衡、故障、安全、时间”分类，只回补最高频的一类；48 小时后重做原题，7 天后做新题。连续两次低于 60 分时，暂缓论文整篇训练，保留每周短案例。

进入 [05｜架构论文](05-architecture-essay.zh-CN.md)；论文训练期间每周继续保留至少一道案例题。
