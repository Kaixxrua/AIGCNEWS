# 03｜系统架构设计师核心知识学习手册

> 用时：第 16～25 周，每周约 6～8 小时。
>
> 目标：把基础认知和系统设计能力对齐到软考上午选择题、下午案例和论文所使用的正式术语。
>
> 说明：具体考试科目、分值、题量和当年度大纲以官方公告为准；本文提供复习结构，不替代官方材料。

## 1. 学习方法：最低充分掌握

不要把教材从第一页读到最后一页再开始做题。每个知识域按以下循环：

1. 先看本手册的最低充分集合；
2. 再读正式教材对应章节；
3. 制作术语卡和概念对比卡；
4. 当天做 5～10 道选择题；
5. 周末闭卷自测并归因；
6. 48 小时后重做错题。

### 三层优先级

- **必须掌握**：能定义、比较、画图，并能处理常见题；
- **应当理解**：能说明用途、边界和架构影响；
- **了解即可**：知道名词属于哪个领域，遇到题再回教材查证。

本阶段仍不要求写代码。数据结构和算法只要求知道思想、复杂度直觉和适用场景，不要求实现排序、树、图或动态规划。

## 3. 知识域清单

### 3.1 组成原理与体系结构

**必须掌握**：计算机分层、CPU、寄存器、指令、内存、I/O、存储层次、总线、并行的基本概念。

**容易混淆**：内存与外存、缓存与主存、指令与程序、吞吐量与处理器频率。不要把频率直接等同于系统性能。

**上午关键词**：局部性、流水线、层次存储、输入输出、中断、DMA、并行/多核。

**架构连接**：服务性能受 CPU、内存、I/O 和网络共同影响；缓存命中减少慢层访问，但引入一致性和容量代价。

**AIGCNEWS 映射**：Redis 的短期缓存和 PostgreSQL 的持久化事实不属于同一存储层；这是职责差异，不是简单的“谁更快”。

### 3.2 操作系统与并发

**必须掌握**：进程、线程、协程的概念差异；调度；临界区；互斥；死锁四条件；虚拟内存；分页；文件系统；I/O。

**容易混淆**：并发不等于并行；锁能保护共享状态但会降低并发；协程轻量不代表自动解决阻塞。

**上午关键词**：互斥、同步、死锁、饥饿、上下文切换、页式存储、缺页、文件权限。

**案例连接**：APScheduler 是进程内调度，横向启动多个实例会产生重复任务风险，需要单活或分布式协调。

**自测问法**：说明“多个采集任务同时更新同一记录”可能产生什么问题，以及锁、幂等和串行化分别解决什么。

### 3.3 计算机网络与通信

**必须掌握**：TCP/IP 分层、IP、DNS、TCP、UDP、HTTP、HTTPS/TLS、连接/延迟/可靠性、反向代理、负载均衡、SSE 与 WebSocket 的定位。

**容易混淆**：TCP 可靠不等于业务请求一定成功；TLS 加密不等于授权；SSE 主要是服务端到客户端流式传输，不是任意双向通信。

**上午关键词**：三次握手、拥塞控制、DNS、TLS、HTTP 状态、代理、会话、长连接。

**AIGCNEWS 映射**：nginx 处于公网边界，承担 TLS、路由、限流和 SSE 代理配置；MCP 是独立协议边界。

**自测问法**：分别说明网络层、传输层、应用层和安全机制在一次 HTTPS 请求中的职责。

### 3.4 数据结构、算法与复杂度

**必须掌握**：数组、链表、栈、队列、树、图、哈希、索引；查找/排序的复杂度直觉；时间与空间复杂度；分治、贪心、动态规划、回溯的基本思想。

**应当理解**：数据规模变大时，线性扫描、对数查找和平方级操作的差异；空间换时间的权衡。

**了解即可**：具体算法代码和竞赛型证明。

**上午关键词**：平衡树、B+ 树、哈希冲突、图遍历、稳定排序、最优子结构。

**AIGCNEWS 映射**：数据库索引、项目检索候选和快照查询体现“以额外结构换取查询效率”，不要求读查询实现。

**自测问法**：为什么数据库不对每次查询都扫描全表？索引会带来哪些维护代价？

### 3.5 数据库系统

**必须掌握**：关系模型、ER、范式、主键/外键、索引、事务、ACID、隔离级别、锁、MVCC、日志、备份恢复、复制、分片、SQL 基本语义。

**容易混淆**：一致性（事务约束）与分布式系统的一致性不是同一个层次；备份不是复制的完全替代；索引不是越多越好。

**上午关键词**：脏读、不可重复读、幻读、乐观/悲观锁、日志先行、故障恢复、读写分离。

**AIGCNEWS 映射**：PostgreSQL 是结构化事实主库；派生索引与主库之间最终一致、没有分布式事务。

**自测问法**：解释为什么“先写 PostgreSQL、稍后更新向量索引”可以成立，并写出新数据短暂搜索不到时的补偿办法。

### 3.6 软件工程、UML 与设计模式

**必须掌握**：生命周期、需求、架构设计、实现、测试、发布、维护；瀑布、迭代、敏捷；风险、配置管理、质量保证；用例图、类图、时序图、活动图、状态图、组件图、部署图。

**设计模式最低集合**：工厂、策略、适配器、观察者、状态、仓储、代理。重点是“变化点在哪里、模式隔离了什么”。

**容易混淆**：UML 图表达不同视角，不是越多越好；设计模式不是必须套用的代码模板。

**AIGCNEWS 映射**：Repository Protocol 与 PostgreSQL 适配器可用来理解“抽象端口与具体实现”的关系；学习只看架构职责。

**自测问法**：同一个系统为什么需要部署图和时序图？分别回答什么问题？

### 3.7 架构风格与质量属性

**必须掌握**：分层、客户端/服务器、管道—过滤器、仓储、事件驱动、SOA、微服务、MVC、六边形、DDD、云原生、Serverless、CQRS、事件溯源；性能、可伸缩性、可用性、可靠性、安全性、可维护性、可测试性、互操作性、可观测性。

**学习方式**：每种风格写“核心组织方式—适用场景—主要收益—主要代价—典型失败模式”。

**容易混淆**：风格不是产品名称；微服务不是天然高可用；CQRS 是读写职责分离，不等于必须使用事件溯源。

**AIGCNEWS 映射**：后端分层与前后端分离；多源采集体现管道/隔离思想；独立 MCP 服务体现协议和部署边界；Compose 是容器化部署形态。

**自测问法**：对一个中小系统，为什么模块化单体可能比微服务更合理？写出至少两个代价。

### 3.8 分布式、云、容器与中间件

**必须掌握**：CAP、BASE、强/最终一致、幂等、重试、消息队列、分布式锁、服务发现、限流、熔断、降级、蓝绿/滚动发布、容器隔离、云服务基本模型。

**应当理解**：分布式系统的难点来自网络、时钟、部分失败、重复消息和数据分散，不是“机器多”本身。

**AIGCNEWS 映射**：跨 PostgreSQL、Milvus、Neo4j、Redis 采用最终一致；调度单活是避免重复执行的运行约束；派生能力可通过补采重建。

**自测问法**：列出一次外部依赖超时可能造成的级联故障，并用超时、熔断、降级、告警和恢复组成闭环。

### 3.9 信息安全、项目治理与标准

**必须掌握**：认证与授权、RBAC、OAuth、JWT、哈希、对称/非对称加密、数字签名、证书、密钥管理、SQL 注入、XSS、CSRF、SSRF、重放、审计、最小权限、备份与灾备。

**容易混淆**：哈希不可逆摘要不同于加密；签名验证完整性和来源，不负责保密；认证回答“是谁”，授权回答“能做什么”。

**AIGCNEWS 映射**：JWT 和 MCP Token/scope 体现身份与权限；nginx/TLS 是边界；用户可控外部 URL 需要 SSRF 防护；凭据应封缄、脱敏、审计。

**项目治理**：范围、进度、成本、质量、风险、沟通、配置和变更控制；架构评估关注利益相关者、质量属性、场景和权衡。

**自测问法**：一个用户已经登录但没有 `projects:favorites:read` scope，为什么仍不能读取收藏？这是认证、授权还是传输加密问题？

### 3.10 云计算、大数据与 AI

**必须掌握**：IaaS/PaaS/SaaS、弹性、容器、对象存储、批处理/流处理、数据湖/仓库的基本定位；训练/推理、RAG、向量数据库、图数据库、Agent/工具调用的架构位置。

**应当理解**：AI 是应用能力的一部分，仍然受数据质量、检索、权限、延迟、成本、评估和可观测性约束。

**AIGCNEWS 映射**：Milvus 面向向量检索，Neo4j 面向论文实体关系，RAG 将多种召回结果交给生成环节；二者不替代 PostgreSQL 事实主库。

**自测问法**：为什么向量库索引重建和权限控制都不能只交给模型解决？

## 4. 计算题最低集合

每周维护一张公式卡，先写变量含义再代数：

| 类型 | 核心关系 | 注意 |
|---|---|---|
| 吞吐量 | 单位时间完成的请求/任务数 | 不等于并发数 |
| 并发 | 同时处于处理中的请求数 | 与平均处理时间共同影响容量 |
| 利用率 | 忙碌时间 / 总时间 | 接近 100% 时排队通常急剧增加 |
| 容量 | 单请求资源消耗 × 请求量 | 需写峰值、平均值和安全余量 |
| 可用性 | 正常服务时间 / 总时间 | 需结合故障检测和恢复时间 |
| 存储 | 单条大小 × 条数 × 副本/增长 | 题设没有数字就声明假设 |
| 网络带宽 | 单位时间传输字节数 | 区分压缩前后和峰值 |

**自测**：题目给出每秒请求数、平均响应体大小和峰值倍数时，先写出带宽估算关系，再说明缓存/压缩/异步会改变哪个变量。禁止只写一个没有单位的数字。

## 5. 选择题训练与阶段验收

### 每日小测

每次 5～10 题，必须在答案旁写一句“本题考的是定义、边界、计算还是权衡”。低于 60% 时当天停止开新章节，先重做错题。

### 第 20 周中测

覆盖组成、操作系统、网络、数据库四域各 10 题。**通过线**：总分 ≥65%，且每域不低于 50%；否则只回补最低域。

### 第 23 周中测

覆盖软件工程、架构风格、质量属性、分布式各 10 题。**通过线**：总分 ≥70%，能口述三种风格的收益和代价。

### 第 25 周阶段验收

1. 完成两套与正式上午科目难度接近的阶段卷；
2. 两套平均 ≥70%；
3. 所有错题完成四类错因归类；
4. 随机抽取 30 张术语卡，正确率 ≥80%；
5. 不看选项解释 CAP、事务隔离、缓存、队列、架构风格、质量属性、安全边界；
6. 完成一张 AIGCNEWS 架构图并在图旁标出至少 5 个考试知识域。

**未通过补救**：按错因最多的两个知识域回看 3 天；第 4 天重做原卷错题，第 7 天做一套新卷。连续两次仍低于 70%，减少选学内容，把时间留给高频核心域。

完成后进入 [04｜下午案例分析](04-case-analysis.zh-CN.md)。从第 18 周起就可以每周做一道短案例，不必等本阶段结束。
