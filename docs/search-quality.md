# 项目搜索质量门禁

## 行为与原因

2026-10-09 的线上只读检查发现：中文“RAG 评估框架”会召回无关资料库，
而 Ragas 没进前十。资料库的原始描述超过 6 万字符，正文深处的关键词被算作
完整匹配；查询里的“框架”又成为中文强制词。完整匹配内部主要受星数影响。

v2 搜索现采用以下规则，Python REST/MCP 与 Go MCP 保持一致：

- 存在技术概念时，“框架 / framework / tool / 工具”不再成为跨语言检索的
  强制字面词；未知项目名仍保留，精确仓库名仍置顶。
- 显式 RAG 请求不扩展到泛化“知识库”；显式知识库请求保留宽召回。
  代码库记忆不再等同于所有编程助手、知识图谱；任务跟踪不再等同于持久记忆。
- 原始描述只取前 1,024 个字符参与 v2 词法召回，加入英文富化描述和双语标签。
  正文、名称/主题、富化标签的功能证据分别计 0 / 1 / 2 分；
  同一概念取最高分，双语重复和多个别名不会重复加分。
- 完整匹配内部，明确索要框架/SDK 时先排用途符合的实现，再排学习资料；
  之后按功能证据、既有相关性/采用度排序。教程查询不受这个降序影响。
- 增加与新检索表达式匹配的两个 GIN 索引（0093 迁移），保留旧索引以支持旧路径与回退。
- 不改变响应字段、权限、筛选、分页或 legacy/shadow 的选择方式。
  不强制开启外部重排服务，不触发生产向量索引全量重建。

## 固定语料与判分

`backend/tests/fixtures/project_search_quality.json` 包含 67 个样本和 28 个查询。
公开项目元数据取自当日 20,746 个符合收录条件的项目；额外加入一个中性的
长描述污染样本，避免把实际无关资料库的长正文提交进仓库。

覆盖 RAG 评估、可观测性、智能体记忆、向量数据库、ASR、TTS、推理服务、
上下文压缩、代码库记忆、任务跟踪、RAG 学习材料，以及精确查找、
未知查询、编程语言筛选。每个发现型需求有中英文配对。

相关性依据项目用途标注：3 = 主要实现或明确请求的学习资料；
2 = 有用的相邻实现/集成功能；0 = 未标注或无关，不计相关。
必找集合独立于返回顺序，漏掉的答案仍进入 NDCG 的理想排序。
未知查询单独要求空结果，不掺入正例均值。

| 固定样本指标 | 改动前 b12b4e58 | 改动后 |
| --- | ---: | ---: |
| NDCG@5（26 个非空需求） | 0.623 | 0.892 |
| 必找项目 Recall@10 | 88.5% | 100% |
| 无关长描述资料库进入 RAG 前十 | 是，中文第一 | 否 |

旧代码运行同一套新门禁会失败，原因是污染样本排在中文 RAG 查询首位。
指标只代表固定回归语料，不代表全部生产查询的相关性。

## 发布门禁与复现

现有 `test_postgres_project_catalog_integration.py` 直接调用质量门禁，
因此现有 PostgreSQL CI 作业会执行它。门禁建立带运行标记的独立 schema，
应用真实迁移、导入语料，调用真实 Python 查询与排序，再调用 Go
`TestProjectQualityReplay` 对同一 schema 只读回放；测试结束只清理自己拥有的 schema。

要求：

- 每例 NDCG@5 ≥ 0.70，整体 ≥ 0.85，必找项目 Recall@10 = 100%。
- 真实 EXPLAIN 验证 v2 查询可使用新索引；迁移测试验证首次应用、重复应用与索引存在。
- 禁入项、精确置顶、未知查询、去重、语言筛选满足契约。
- 中英文配对前五一致，全部 28 例 Python / Go 前十顺序完全一致。
- REST 分页与 MCP 对齐；向量服务报错或注入高分无关结果时，
  完整词法答案的前五保持稳定。

本地需要后端测试环境、Docker 与 Go 1.26：

```bash
TZ=UTC scripts/run_postgres_integration_tests.sh \
  backend/tests/test_postgres_project_catalog_integration.py
```

可加 `-k quality_release_gate -s` 单独运行质量门禁。报告与两侧原始结果
保存在 pytest 的临时目录；无测试 DSN 的普通后端单测会跳过数据库门禁，
发布流水线的 PostgreSQL 作业必须运行它。

## 全量公开语料回放的边界

本次另在隔离 PostgreSQL 中回放了全部 20,746 个公开项目的 26 个查询，
使用 v2、采用度权重 0.006、关闭外部向量与重排，复现了原始问题。
改动后，中英文 RAG 评估均以 promptfoo、Ragas 开头；
代码库记忆以 codebase-memory-mcp 开头；
任务跟踪均以 claude-task-master 开头，beads 位于第三。

同机隔离数据库上的两轮耗时观察：RAG 查询由未补索引时约 2.1 秒回到
0.68 秒左右（旧查询约 0.62–0.76 秒）。代码库记忆约 0.47 秒、向量数据库
约 0.35 秒，比旧实现约 0.38 / 0.26 秒有所增加。数据、字段和排序证据更丰富，
这里不宣称所有查询都更快；这些是开发环境观察值，不是线上延迟承诺。
20,746 条已有数据上的新增索引迁移用时约 2.6 秒，第二次应用为空。

这份全量快照不进入仓库，也未写入生产数据库。它证明了词法检索及排序的改善，
不等同于对线上向量模型、外部 GitHub 降级与可选重排模型的全面质量评估。
今后新增事故应补充用途标注与负例，不能只更新期望返回顺序或下调门槛。
