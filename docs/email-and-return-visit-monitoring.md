# 邮件监测与每日账号回访

监测页新增「邮件监测」；「用户统计」下方展示每天的全部访客 UV、登录账号、老账号、
当日新账号、回访比例及每日注册率，支持最近 7 / 30 / 90 天，默认 7 天。两个读取接口均仅管理员可用，
响应不缓存；邮件面板刷新只读，不发测试邮件。

## 全站访客回访

- 监测页直接展示原有每日访客、账号及注册率，历史数据与今日全部 UV 始终可见。
  全站访客回访在下方独立展示；首日显示采集进度，之后仅展示已开始采集的日期，
  避免用新口径的局部 UV 或采集前空表替代原有统计。统计口径说明可展开查看。
  现有 GET /api/monitor/user-return-visits 增加 `visitor_returns` 对象，包含独立的
  `tracking_started_at`、`as_of`、`timezone` 和逐日 `days`，原响应字段及含义保持兼容。
- 自然日仍为 Asia/Shanghai；同一浏览器标识的最早观测日期早于统计日，就算回访，
  不限于此前 7 天。7 / 30 / 90 天只控制展示范围。未注册用户同样计入；
  当日注册前曾在其他日期访问的浏览器也计入，首次到访当天注册不会自动成为回访。
- `visitor_returns.days[].return_rate = returning_visitors / total_visitors`。
  分子与分母都来自同一组持久化浏览器日记录，包含当天新注册对应的浏览器，
  不再扣除新账号，不把账号数与浏览器数相加。这里的 `total_visitors` 是新采集覆盖的 UV，
  与外层原站点累计计数独立；上线首日、计数故障或重试期间两者可能不同。
- 复用前端已有匿名 ID；注册、登录不重置，服务端只保存其 SHA-256 摘要及日期，
  不保存 IP、原始匿名 ID 或账号关联。不同设备、不同浏览器不合并；清除站点数据、
  无法使用浏览器存储、未发送上报或写入失败仍可能漏计。指标表示浏览器回访占比，不是留存率。
- 0099 迁移仅新增采集起点、浏览器最早日期和浏览器日记录，不改写历史计数。
  采集前所有浏览器计数及比例为 null；首日没有跨日历史，回访人数及比例为 null，
  但已采集 UV 可展示。首日、当日标为 partial，完整已采集日标为 complete；
  无访客时比例为 null。只识别采集以来的历史，初期可能低估真实回访。
- 浏览器最早日期与当日事实在同一事务写入；主键抵御并发、多标签页及请求重试。
  午夜前后的请求乱序完成时仍保留最早日期。每次非机器人 beacon 均尝试幂等持久化，
  包括 Redis 已去重的请求；数据库失败先返回 503，不消耗 Redis 的日内去重状态。
  原站点总量与来源统计继续使用原路径及响应；Redis 故障时原总量路径仍返回 503，
  已成功持久化的浏览器事实保留，重试不重复计数。已识别机器人不写浏览器历史。

## 账号统计（原口径）

- 自然日固定为 Asia/Shanghai。`total_visitors` 为全部访客 UV（包含未登录访客），
  与站点访客计数共用 `site_visit_days.visits`；`returning_users` 为当日访问且在当日
  00:00 **之前**注册的唯一账号数，包含管理员；`active_users` 为登录访问账号数。
  `new_users = active_users - returning_users`，只包含当天注册且成功记录网页访问的账号，
  不等于 users 表中的当天全部注册数。
- `return_rate = returning_users / (total_visitors - new_users)`，排除当天新账号；
  新增 `registration_rate = new_users / (total_visitors - returning_users)`，排除已知回访账号。
  这是有意调整旧 `return_rate = returning_users / total_visitors` 的业务口径；已有计数及
  路由保持不变，历史可用日期也按新公式计算，不改写原始记录。
  例如 2026-10-12 的 UV 为 453、老账号为 9、新账号为 96，则分别为 9/357 ≈ 2.52%
  和 96/444 ≈ 21.62%。
- 全部访客沿用浏览器匿名 ID 的 Redis 日内去重，排除已识别机器人；
  它不是页面浏览量，也不是自然人数量。换浏览器、清除站点数据会产生新 ID；
  Redis 去重状态丢失可能造成重计，beacon 未发送或写入失败可能漏计。
  分子及扣除项按账号、UV 按浏览器，两者身份口径不同，未登录的老账号也无法排除。
  因此两个比例都是经营分析的估算值，不是精确注册转化率，也不是老用户留存率；
  计算精确转化率须将注册事件与访客身份关联，计算留存率须按同一注册日期的人群跟踪后续回访。
  不对异常比例强行截断或用登录数补分母。
- 登录账号在页面处于前台、登录恢复/切换、重新联网和跨午夜时上报。
  MCP/API 调用及可识别机器人不计入；未登录访客只计入分母。
  数据以服务端成功收到的访问记录为准，不代表次日留存率。
- POST /api/dashboard/account-visit 只采用 RequireUser 验证的身份；
  注册时间来自 users。客户端不能指定用户、日期或是否回访。
- PostgreSQL 的 (day, user_id) 主键在并发、重试、多标签页、多设备情况下
  都只保留一条事实，不依赖浏览器存储或 Redis。删除账号不改变历史聚合。
- 0095 迁移记下账号采集起点。更早日期的账号数及比例返回 null，已存在的访客 UV
  历史仍可展示。上线首日及当前日标为部分数据，各自扣除后的分母小于或等于零时该比例为 null；
  仅有匿名访客且账号采集已开始的日期为 0%。同一 SQL 快照读取分子、分母，
  后端返回未舍入的比值，页面显示两位小数和分子/分母。
  网络中断、客户端未运行上报或尚未更新到新前端的访问不能事后补算。

## 邮件与告警

后台随 scheduler_enabled 启用，每 5 分钟检查一次，首轮启动后执行。
数据库租约在多进程间防止重复检查。超过 10 分钟无成功检查，面板标记数据过期。
SMTP 配置和邮件池使用与实际发送一致的 DB 优先解析，不复用旧环境端口。
SMTP 探测只连接、认证、NOOP，不消耗发送额度。

本站 EmailService 为验证码、传统简报订阅及推送渠道简报记录
accepted/failed；不保存地址、内容、标题或验证码。accepted 表示 SMTP 接受，
不表示收件方已送达。记录保留 90 天，页面展示滚动 24 小时，上线前不补算。

Resend 的 /usage 是账户真实用量和额度，以 API 返回的 reset 时间为准；
账期不强行等同自然月。/emails 展示最近最多 100 封的最新状态，包含同账户其他
应用发送的邮件，不能当作某天的完整投递统计。多配置共用一个账户时不相加。
未接入、读取权限不足或接口失败都显示不可读，不显示伪造的零额度。

告警条件：近 15 分钟实际发信失败、SMTP 连接/认证失败、Resend 用量达到
80% / 95% / 100%、最近样本中近 24 小时异常投递、服务商监测接口读取失败。
告警记录先持久化再发送；同故障只提醒一次，级别升级或恢复后复发重新提醒。
每类故障保留最近一次状态。配置移除会解除对应旧告警，读取失败不会误解除额度告警。
告警记录的 `current_detail` 随成功检查更新，`detail` 保留首次触发内容用于幂等重试；
旧快照没有 `current_detail` 时页面回退展示 `detail`，不会仅因数量变化重复通知。

收件人为 AIGCNEWS_OPS_ALERT_TO，未指定时沿用现有运维策略回退实际 SMTP
发件邮箱。可在部署环境中覆盖该变量。告警选用 Resend HTTPS，避免 SMTP
故障连带阻断告警；若无 Resend 则使用首个 SMTP 通道。HTTPS 请求仅发往
固定 api.resend.com，禁止跳转，使用服务端出站代理；非 Resend 密钥不会发给 Resend。
面板通过 `recipient_source` 区分显式配置、回退发件地址和缺少地址；后两种情况提示配置
可收信的运维邮箱。发件域名验证通过不代表地址具有收信能力，回退提示不等同于 DNS 检查。
“已提交发信服务”只确认提交回执，尚未核验最终送达，退信或延迟仍须检查服务商投递记录。

相同 Resend 告警重试使用相同消息和幂等键。提交成功后停止；失败每小时最多
重试一次，仅在故障持续时重试；首次尝试 23 小时后停止自动重发，以免越过服务商 24 小时幂等窗口。
普通 SMTP 无幂等回执，不自动重试不确定结果。页面区分已提交与未确认发送，
失败记录保留供人工核验。额度耗尽或 Resend 整体故障也可能阻止告警邮件，
提前阈值告警及页面记录仍保留；目前没有独立第二告警服务。

服务商协议依据：[Resend 幂等键](https://resend.com/docs/dashboard/emails/idempotency-keys)。

## 验证

backend/tests/test_monitor_activity_integration.py 在独立 PostgreSQL 测试库验证迁移、
并发唯一约束、CST 日界、注册日边界、历史不可用、空分母及检查租约。
test_routes_monitor_activity.py 检查身份伪造、匿名/普通用户越权及读接口无发信副作用。
test_email_monitor.py 验证额度、故障、重启去重、通知协议和重试窗口。
前端覆盖登录后上报、隐藏页排除、跨午夜、重试、账号切换与页面状态。

test_postgres_visitor_return_repository.py 使用独立 PostgreSQL 验证匿名回访、注册前后
同标识、超过 7 天的旧访客、并发去重、午夜乱序、事务回滚、摘要持久化及迁移重复执行。
test_site_visit_routes.py 覆盖机器人排除、客户端日期伪造和失败重试；前端验证默认 7 天、
新旧口径分开显示、采集前与首日空值、有效零值及旧接口响应兼容。
