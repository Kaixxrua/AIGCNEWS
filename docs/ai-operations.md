# AI 运维

管理员进入 `/monitor?section=ai-ops`，点击「立即巡检」。复用后台「模型服务」当前保存的配置，运维调用单独使用 high 推理档位；没有可用模型时运行显示失败，保留已收集证据，不伪造 AI 结果。可开启自动巡检，间隔 5–120 分钟，默认关闭。自动巡检由应用生命周期管理，关闭浏览器仍执行。

活动记录每两秒刷新，展示工具开始、证据、模型调用、修复动作、回访与最终报告，不展示模型隐式思维过程。调查记录保存在 PostgreSQL，保留 30 天、页面显示最近 50 次。取消阻止后续步骤和结果覆盖；已经准入的动作仍保留执行与回访结果。单次调查总预算 300 秒，过期运行 6 分钟后标记中断；跨 worker 使用数据库锁防止重复准入。

## 固定诊断与降级

代码直接采集固定白名单，最多三个查询并行，每项最多等待 25 秒，不再调用模型安排查询顺序。模型仅用于选择已有修复候选（最多一次、60 秒）和生成报告（一次、120 秒）。单项查询失败标记 unavailable，其他证据仍保留；报告模型不可用或调查超时会留下明确标注的程序摘要，调查状态仍是 failed，不能冒充 AI 分析成功。

| 工具 | 范围 |
| --- | --- |
| health | Milvus、Neo4j、可选 Ollama、PostgreSQL、Redis 探针 |
| tasks | 最近 15 条采集任务元数据，不包含 error_msg |
| errors | 24 小时错误总量；最近最多 1000 条本地分类，按指纹合并后返回最多 20 组 |
| source_trends | 各已知数据源当前/前一个 24 小时失败数量、产出、48 小时窗口内最近成功与失败 |
| database | 当前数据库连接、活动查询、锁等待和空闲事务数量；不含 SQL、参数、用户或主机 |
| investigation_history | 最近 24 小时调查状态和失败阶段统计 |
| scheduler / delivery | 调度状态与带新鲜度的交付快照 |
| x_translations | 译文队列数量、陈旧租约、最近成功时间与本地分类后的错误类别 |
| followups | 最近 20 项自动操作的后续验证状态、验证范围和截止时间 |
| knowledge | 根据上述证据匹配的版本化故障手册及最多 10 项同策略版本的历史验证案例 |

错误原始消息只在服务器内做分类。模型收到固定描述、异常类型、模块和最多三个应用堆栈位置；不发送日志正文、堆栈代码行、URL、凭据、邮件地址、用户内容或任意磁盘路径。X 译文工具和候选也不再发送原始 last_error。样本数量与截断标记明确区分于全量统计；窗口中没有成功不能推断从未成功。数据库查询另有 5 秒语句预算。

队列状态只证明任务是否积压，不能据单个陈旧任务断言页面退回英文或全站故障。Ollama 是可选本地依赖，不代表外部模型服务。报告作为纯文本显示。

## 故障手册与经验

首批代码审阅的手册覆盖 X API、X 译文、arXiv 下载、邮件投递、数据库查询/锁等待、模型超时和程序契约异常。每份包含适用条件、必查证据、排障步骤、验证标准和策略版本；按错误来源、类别及队列状态匹配，不依赖额外向量库或外部运维平台。设计参考 [HolmesGPT Skills](https://holmesgpt.dev/latest/reference/skills/)，无新增依赖。

`ai_ops_followups` 独立于 30 天调查历史保留，记录动作、具体目标、操作前条件、策略版本、可用时的生产 SHA，以及代码观测的后续结果。仅 verified / not_recovered 进入历史案例，pending、inconclusive 和模型猜测不进入经验。返回模型时去除任务 ID 集合。旧案例不是本次根因，也不授予执行权限；必须重新核对当前版本与条件。

## 有限自动修复

自动巡检与「有限自动修复」分别控制调查准入和动作准入；旧客户端省略 recovery_enabled 时保留现值。所有动作仍受取消检查、代码前置条件、原有预算与审计约束。模型只能选择代码生成的候选 ID，不能生成操作名、参数或命令。

- **资讯失败补跑**：仅 Techmeme、Hacker News、DailyHot，最新同名失败、零产出、结束于 5–60 分钟前且明确为网络暂态错误；鉴权、限流、程序异常拒绝。同源运行中、正常调度不足 5 分钟或交付非新鲜 delivered 均拒绝。每小时最多一次、每天三次、每个失败任务终身一次。
- **僵死采集任务收尾**：超过 6 小时的 running 任务，单轮最多 200 条；每天最多 4 次、间隔至少一小时。保留原 item_count，并标明中断遗留。
- **X 译文重试**：有待重试任务且至少 30 分钟无成功推进；仅剩过期租约也可形成候选，有有效租约则等待。执行前恢复陈旧租约并重新检查活跃批次，最多提交 200 条；每天最多 6 次、间隔至少一小时。
- **简报补生成**：北京时间 10:30 后原调度重试已结束，对应日期/维度仍缺失且简报错误已安静 30 分钟；按原派发链提交。每个目标每天最多 2 次、合计 10 次、间隔至少一小时。生成与邮件投递分别判断。

以上是已有动作范围；没有新增 shell、凭据/配置修改、部署、回滚、数据库重启或任意 SQL 执行能力。代码修复继续走 session → 精确 SHA CI → 串行落地 → 标准发布。撤销权限与取消不能撤回已准入的动作；结果仍进入审计。

## 修复回访

动作结果与回访登记在同一数据库事务内保存，以动作 ID 去重。submitted / scheduled 仅表示已提交；completed 也只说明同步动作结束。首次回访在两分钟后，观察期内每两分钟再查，最长两小时，允许五分钟调度误差，长期停机错过窗口记为证据不足；每批最多 20 项，跨 worker 锁定并跳过已锁定项，终态只记录一次。应用重启后从账本继续，关闭自动巡检或撤销未来修复权限仍会继续只读业务回访；不会重放动作。

- 译文：跟踪提交时的目标任务集合，必须全部 succeeded 且译文非空。无关新任务成功不算目标恢复。
- 资讯：原失败任务之后、提交之后开始的同名采集，必须 success 且有产出。只能证明后续恢复，不能归因于某次补跑。
- 简报：核对精确日期/维度缓存键和非空内容，只证明生成；不宣称邮件投递成功。
- 僵死任务：核对目标任务已标为中断失败，只证明收尾；不宣称采集业务已恢复。

结果为 verified（已核实指定范围）、not_recovered（观察期结束仍未恢复）、inconclusive（缺失证据）。回访事件会追加到原调查，已完成或取消的调查也可查看。案例保留证据范围；陈旧或缺失证据不会被视为成功。

## 自动交付快照

控制器在宿主机，后端在容器。只读桥每 30 秒把控制器 `status.json` 的允许字段投影到已有 metrics 挂载目录，不挂载控制器数据库、凭据或 Docker socket。安装示例（实际路径按部署配置填写）：

```bash
python3 scripts/ai_ops_delivery_bridge.py --install \
  --source /home/kaixxrua/.local/state/aigcnews-local-delivery/status.json \
  --destination /home/kaixxrua/AIGCNEWS-production/storage/metrics/ai_ops/delivery.json
```

生成时间保留上游时间，超过 180 秒标记 stale；桥失败不能用复制时间冒充数据新鲜。缺失时明确 unavailable，不推断部署成功。管理员可以在 delivery 工具结果中检查 `main_sha`、`active_sha` 与任务状态。桥不改变原控制器的 CI、唤醒、合并和发布流程。

停用桥：`systemctl --user disable --now aigcnews-ai-ops-bridge.timer`。停用自动巡检在管理界面保存开关；既有运行需单独停止。

## 验证

覆盖固定工具白名单、取消、模型超时降级、脱敏及提示注入边界、故障手册匹配、原有动作权限与预算、陈旧/活跃租约、真实 PostgreSQL 迁移与并发回访、历史保留、前端实时刷新与 XSS 文本显示。运行记录只是调查证据；completed 表示调查已完成，不等于服务健康或修复完成。
