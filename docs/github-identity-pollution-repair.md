# GitHub 仓库身份污染修复（2026-10-08）

## 问题与行为修复

`feder-cr/invisible_dots`（`R_kgDOMfGEzA`）与
`feder-cr/invisible_playwright_mcp`（`R_kgDOUz_Frw`）是不同仓库。
错误名称别名与改名合并使约 2,600 星和 31,800 星的历史进入同一时间序列，
造成虚假增长和热度跳变。旧版以 node ID 为主键的行也存在同类问题。

写入入口现在共同校验稳定身份：

- 改名合并时检查来源、目标两侧已知 node ID；任何一侧不匹配即拒绝合并。
- 将旧版 node 型主键本身计入身份依据；数字型 REST ID 不直接与 GraphQL ID 比较。
- 名称写入优先匹配当前同名实体；只有历史别名而没有稳定身份依据时拒绝跨仓写入。
- 同批次两个不同 node ID 声称同一名称时跳过冲突项；事务级 advisory lock 保护并发首次发现。
- 最新完整 API 观测允许纠正虚高的候选 star/fork/watcher 数，过时完整观测不能反向覆盖。
- 快照允许更正明确提供的创建日期，并保留已有时间精度；缺失日期的输入不覆盖明确日期。

REST/MCP/SSE 的响应字段未改变。变化集中在冲突写入的拒绝、当前计数纠正与历史指标修复。

## 可复用维护工具

在具有正确 PostgreSQL 配置的后端环境中执行：

```bash
python scripts/audit_github_identity_pollution.py --verify-github > /outside/repo/audit.json
python scripts/apply_github_identity_repair.py /outside/repo/reviewed-plan.json
python scripts/apply_github_identity_repair.py /outside/repo/reviewed-plan.json \
  --apply --backup /outside/repo/new-preimage.json
```

审计工具只读；外部核验不会写入观测、别名或计数。报告包含名称冲突、node 主键/别名冲突、
创建日期异常、大幅降星及对应原始元数据。不要将 token 或数据库连接串放入报告。

修复清单指定数据库/schema、白名单表、精确主键、预期旧值和目标字段。
工具先锁定有关表并检查所有旧值；默认只预演这些检查。
预演不会执行写入，不能提前保证所有数据库约束都通过。
正式执行前以 `0600`、独占新文件和 `fsync` 保存完整行备份，所有写入位于同一事务；
约束失败则整体回滚。跨仓移动必须明确列出原行删除与新行插入。
不要盲目重放已执行清单或覆盖备份；回滚也应核对当前值，以免覆盖后续正常采集。
