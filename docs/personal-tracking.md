# 个人情报追踪（VIP 首版）

入口位于登录后的「我的订阅 → 我的情报追踪」。免费账号最多保存 1 条规则，生效 VIP 最多 10 条；额度由数据库中的实时会员状态决定，客户端或 JWT 中的会员声明不能提升额度。暂停的规则仍占保存名额。会员到期保留全部规则，按创建顺序执行最早启用的 1 条，其余可编辑、暂停或删除。

## 当前能力

- 关键词：最多 8 个词，空格分隔，每个词都要出现在标题、摘要或 X 帖子的中文译文里；可限定内容来源，最多 10 个排除词、每个 40 字。含英文字母的纯 ASCII 关键词与排除词按英文词边界匹配，不区分大小写，边界为非英文字母、数字或下划线：`RAG` 可命中 `rag`、`Graph-RAG`、`RAG系统`，不会命中 `storage`、`coverage`、`RAG2` 或 `GraphRAG`。符号按字面匹配，例如 `C++`、`a.b`；中文等非 ASCII 词组继续按包含关系匹配。预览与每日汇总使用同一匹配逻辑；此修复不改写历史简报。
- 中文词的英文同义词：中文关键词或排除词整词在内置词表里时，同时按英文词边界匹配它的英文同义词，允许复数 s。例如「智能体」也命中 `agent`、`AI agent`、`agentic`，「大模型」命中 `LLM`；排除「融资」时一并排除 `funding`、`Series A`。只扩展整词，「智能体平台」不扩展；英文关键词不反向扩展；「代理」这类在资讯里有歧义的词不扩展。词表取自项目搜索的概念表，另补常见的资讯、公司与人名词，并去掉 `learning` 等在资讯里会误中的别名；项目搜索行为不变。
- 项目增长：填写 GitHub `owner/repository` 或项目链接，使用本站已有的每日 Stars 增量，达到设定阈值后汇总。仅覆盖本站已收录、达到公开项目门槛的项目；这一版不监测版本发布或任意外部仓库。
- 匹配预览：查看最近 24 小时，不发送通知、不写入去重记录。显示命中总数与各来源条数，超过 50 条时只列最新 50 条、总数仍按全部命中计；中文词扩展了英文同义词时逐条说明。
- 每日个人简报：可选北京时间 0–23 点，沿用每 30 分钟的订阅调度器。首次检查最近 24 小时，后续接续上次检查时间；中断最多补查 7 天。无新匹配时不生成空简报。
- 同一内容命中多条规则时合并，并标明匹配规则；每期保留最新 50 条，超限显示提示。页面显示最近 7 期；活跃生成时清理超过 90 天的历史及去重记录。
- 热度飙升提醒（仅生效 VIP）：生成简报时，每个关键词按规则的同一匹配条件，以生成时刻为终点向前数 8 个 24 小时窗口计数。已推送过的内容也计入，量的是热度而不是新内容。最近 24 小时至少 5 条，且不少于前 7 天日均的 3 倍（日均不足 1 条按 1 条算）时，在该期顶部标出「热度飙升」，写明近 24 小时条数和前 7 天日均（保留一位小数）。同一窗口内同来源全部内容为 0 的日子视为采集中断，不计入日均；前 7 天都中断时不提醒。多条规则用同一关键词只算一次，按倍数从高到低排列。项目增长规则和免费账号不计算。提醒随简报生成，不为它单独生成简报。邮件等渠道在标题下以引用行显示。阈值按生产数据校准，常见关键词大约每月触发一次。
- 历史导出（仅生效 VIP）：在「最近的个人简报」标题旁导出最近 90 天生成的简报，与保留期一致。CSV 一行一条结果，列为期号、时间、来源、标题、链接、匹配规则（多条用 `; ` 分隔）、摘要；带 UTF-8 BOM，可直接用 Excel 打开。以 `=`、`+`、`-`、`@` 或制表、换行符开头的单元格前加 `'`，表格软件不会把它当公式执行。JSON 另含全部规则（不含内部编号）和每期的热度飙升。会员资格按数据库里的实时档位判断，令牌里的会员声明不算；到期后不能导出，数据照常保留。免费账号在同一位置看到开通入口。
- 默认仅在本站查看。用户可主动选择自己的已验证、启用的邮箱、Webhook、Discord 或 Telegram 渠道；沿用现有渠道验证、密钥和出站安全检查。没有启用新的外部抓取或个人 LLM 调用。

## 接口与一致性

全部新接口位于 `/api/tracking`，使用现有 Bearer 登录认证：

| 方法与路径 | 行为 |
| --- | --- |
| GET `/api/tracking` | 额度、规则、设置、最近简报；每期简报含 `surges`（热度飙升，免费账号和存量简报为空列表） |
| GET `/api/tracking/unread` | 当前账号最新期号、已读期号及是否未读；不返回内容、不生成简报 |
| POST `/api/tracking/read` | 以 `digest_id` 确认已显示的个人简报，不能提交其他用户的期号 |
| POST `/api/tracking/rules` | 创建规则，成功 201 |
| PUT `/api/tracking/rules/{id}` | 完整更新自己的规则 |
| DELETE `/api/tracking/rules/{id}` | 删除自己的规则，保留简报 |
| GET `/api/tracking/export` | 生效 VIP 下载最近 90 天简报：`format=csv`（默认）或 `format=json`；以附件返回并带 `Cache-Control: no-store`。免费或到期账号回 403 `membership_required` |
| GET `/api/tracking/rules/{id}/preview` | 预览生效规则：`items`、`truncated`，以及 `total`、按条数降序的 `sources` 与 `expansions` |
| PUT `/api/tracking/settings` | 更新汇总时间、启用状态、可选渠道 |

创建规则先锁定用户记录，避免并发突破额度。摘要生成锁定用户设置，并由 `(user_id, issue_date)` 唯一约束防止重复生成。投递使用 `SKIP LOCKED` 领取、10 分钟租约和最多 3 次尝试；过期发送者不能确认新租约。修改渠道不会将旧队列改投到新渠道。暂停、删除渠道或账号停用后，尚未领取的投递会取消。

外部发送与数据库确认不能组成同一事务；进程在发送成功但确认前退出时，重试可能重复投递，不承诺 exactly-once。已在发送途中的消息无法撤回。

## 数据库与发布

迁移 `0069_tracking_read_cursor.sql` 增加账号已读游标及最新期号索引。新结果生成后，桌面和手机 Dock 的「情报追踪」显示红点；历史简报默认未读。只有所选简报的首条结果至少一半进入可见区域，且浏览器标签页可见时，才提交该期号的已读回执。打开路由、失败加载、关键词编辑和匹配预览均不清除红点。查看最新一期会确认该期及之前的更新；随后新增的期号仍保持未读。

已读游标仅前进，服务器验证期号归属；重试、多设备及迟到轮询不能倒退状态。回执失败保留红点，在结果仍可见时重试。全站登录后每 60 秒轻量检查，隐藏标签页停止检查，回到页面时更新；退出账号立即清理内存状态。此通知不调用 LLM、不额外生成简报、不修改原有内容去重游标。应用回退时可保留新增字段与索引。

迁移 `0086_tracking_digest_surges.sql` 为 `tracking_digests` 增加 `surges` JSONB 列，默认空数组，并约束必须是数组。它只加列，不改写存量简报；回退应用版本时可保留该列。每个会员关键词每天多一次按天分组的计数查询，生产数据实测每次约 0.1–0.14 秒。

新增迁移 `0067_personal_tracking.sql` 创建设置、规则、摘要和去重表；所有业务记录按用户外键级联删除。保留线上既有的 `0065_oauth_identity_owner_provider_unique.sql` 与 `0066_recommended_websites.sql`，不改写旧迁移及其台账。原交付包中的追踪迁移在发布前顺延为 0067，以兼容已上线的站长推荐迁移。

发布时先通过项目既定迁移流程应用迁移，再启动新后端和新前端；调度器随新后端生效。回退应用版本时可保留新增表，不需要删除用户规则。现有 REST、MCP、SSE 接口及 MCP 配额数值保持原行为，会员文案把日额度和 30 日额度表述为同时生效的上限。

隔离预览使用示例账号和独立 PostgreSQL，不连接线上账号或启动推送调度。源码和预览完成不表示已发布到公网。
