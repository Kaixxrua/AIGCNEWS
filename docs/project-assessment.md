# 项目试用判断

热度描述关注度；试用判断帮助读者确认用途、人群、上手条件和限制。两者独立，不把星数、增长或分类置信度换算成质量分。

## 证据与筛选

GitHub 富化增加双语 assessment，持久化在 enrichment 的可空 JSONB 列中。每项判断须附 description 或成功 README 快照中的原文，后端验证引用确实存在于提供给模型的资料中。README 输入最多 20,000 字符；失败快照、截断部分和编造的引用不能支持判断。引用匹配证明来源存在，不保证推理正确，因此界面明确标为文档自动判断、未经实测。

新入口 `/projects?scope=screened` 只展示当前有效、AI 相关且有用途、适用人群及 README 上手依据的项目。“可评估试用”表示有足够资料开始评估，不代表生产就绪、可靠性认证或商业许可。无证据的限制、硬件和费用等信息显示待核实，不生成“没有限制”“免费”“安全”等兜底结论。实验状态等明确限制仍展示给读者，不因披露限制而被淘汰。

与 AI 无关的项目标记为偏离主线；证据不足的项目不能进入新筛选。原有全库、今日热榜、人工推荐、收藏和 MCP 输出字段保持原语义。筛选在 SQL 分页和关键词候选截断之前执行，合计与页内结果来自同一条件。

## 刷新与兼容

新富化随正文一起生成判断。每日 GitHub 主流水线在新项目富化后，优先按当前热度、星数为已有项目补评，默认每次最多 20 个、仓储上限 50 个；累计三次模型错误便结束本批。补评只更新判断，模型失败不会把原项目改成富化失败或下架。并发写入以 enrichment.updated_at 比较后更新，避免较慢评估覆盖新结果。

README 摘要、原始简介或许可变化，以及评估超过 30 天，都会立即使旧判断失效；页面回到未评估，项目退出新筛选并等待补评。旧条目保留，迁移不触发全库模型调用，也不编造历史判断。当前 README 抓取失败时先等待成功快照，不用失败数据推断。

## 验证

契约测试覆盖无证据高星项目、原文不匹配、截断/失败 README、模型伪造推荐等级、双语字段、补评失败保留正文。隔离 PostgreSQL 16 测试执行完整迁移并验证落库、REST 筛选、关键词候选、来源失效和并发更新。前端验证中英文、未知项提示、可展开的原文及 HTML 转义，并在桌面和手机检查交互。

2026-10-14 使用现有模型配置对两个真实条目作只读抽样：VoiceStudio 进入可评估试用，保留 Beta、GPU 要求与语言覆盖限制，8 条分组判断中 7 条通过原文校验；xtool 根据其 Xcode / iOS 工具用途归为非 AI 主线。抽样不写生产数据，不能视为整体内容准确率或项目实测结果。
